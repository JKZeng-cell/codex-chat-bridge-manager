# v1.0.5 · 消息回复与平台 CLI / Replies And Platform CLIs

## 更新内容

- 修复企业微信绑定：未扫码的 `init` 状态不再误报为拒绝授权；未知中间状态保留二维码等待，真实拒绝与超时仍正常处理。
- 各平台通过权限校验并入队后发送接收确认；重复或未授权消息不会重复执行。
- 飞书卡片增加公开答复预览；企业微信原位更新流式消息；钉钉使用官方 AI 流式卡片，权限不足回退文本；微信按完成段落发送。
- 流式回复支持节流、串行投递、最终结果收口与长中文分片，推理和命令日志不参与实时回复。
- 增加钉钉 DWS、企业微信 CLI 的版本检测、独立授权、二维码/授权链接与取消操作。
- 安装包内置企业微信 CLI 1.3.4、钉钉 DWS 1.0.65 及 31 项官方技能，无需另装 Node.js 或全局工具；授权后可点击「启用并连接」。
- 每个机器人使用独立 CLI 配置，启用「平台 CLI」并保存连接后才向 Codex 注入平台调用指引；未安装、旧版或未授权状态有明确提示。
- 包含 1.0.4 的托盘后台运行与安装器正常退出兼容，不强制结束忙碌任务。

## 使用方式

连接设置 → 内置 CLI 面板 → 授权 CLI → 手机确认 → 启用并连接。
官方技能按请求类型自动提供给 Codex 读取，也可在技能页查看。
工具与技能随应用更新，固定来源并校验完整性；不会覆盖全局工具、已有技能或其他机器人的授权。

钉钉卡片要求互动卡片写权限和 AI 流式更新权限。微信为分段回复而非原位逐字编辑，
实际更新频率受 Codex 输出事件和平台接口限制。企业权限需要用户/管理员批准。

## English

Fix WeCom's unscanned `init` state being mistaken for denied authorization. Preserve
QR waiting for intermediate states while retaining expiry and explicit-denial handling.
All platforms acknowledge accepted requests. Stream public answers through Feishu
cards, WeCom messages and DingTalk AI cards; DingTalk falls back to text if cards fail,
and WeChat sends completed segments. Throttling, ordered finalization and UTF-8 chunks
avoid stale final updates and truncated long answers.

Add version detection, scoped authorization and cancellation for official DingTalk DWS
and WeCom CLI. Native WeCom CLI 1.3.4, DWS 1.0.65 and 31 official skills ship in the
desktop package; no Node.js/global installation is required. Authorize in connection
settings, then click Enable And Connect. Skills are loaded on demand without writing
to global user skill directories. Artifacts are version-pinned and integrity-checked.
Existing credentials/skills are not copied or automatically replaced.
The v1.0.4 tray and protected installer-quit improvements are included.

See [validation scope](../VALIDATION.md). Protocol/GUI simulations are not proof of
live phone authorization, enterprise permission grants or all-platform delivery.
